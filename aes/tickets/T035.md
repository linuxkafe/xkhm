# T035 — Os serviços do cliente, pelo seu tipo

## Contexto

O operador: «não vejo os serviços subscritos por utilizador estão todos
definidos como alojamento web quando há serviços diferentes».

E tem razão. A secção «Alojamento» do detalhe do cliente lista as
linhas de `tblhosting` — **todas** com o mesmo tratamento. Mas
`tblhosting` não é só alojamento web: é a tabela dos **serviços**, e o
que distingue um serviço de outro é o **produto** ao qual pertence.

## Reconhecimento

| Facto | Evidência |
|-------|-----------|
| `tblhosting` é a tabela dos **serviços** (não só do alojamento web) | 10 linhas, todas com `packageid` |
| O produto diz o **tipo** do serviço | `tblproducts.type`: `hostingaccount` (8), `other` (14), `server` (2) |
| O **grupo** diz a família | `tblproductgroups`: Web Hosting, Assistência Técnica, Servidores Virtuais, Servidores Locais, Gestão Empresarial, **Backup** |
| 3 dos 10 serviços são de **Backup**, não de alojamento | `tblhosting.id` 60, 61, 62 → grupo 6, tipo `other` |
| O nome real do serviço está no produto | «LINUXKONECT XK10», «Backup Offsite - Servidor Extra» |
| A **app** não mostra serviços de todo | `GET /api/v1/client/summary` devolve só contagens |
| O `domainstatus` é um `enum` | `Pending, Active, Suspended, Terminated, Cancelled, Fraud` |

## Scope

### In scope

**O painel**
- A secção passa a chamar-se **Serviços**, e cada serviço mostra o seu
  **tipo** (o nome do produto e o grupo), não "alojamento web"
- Os serviços são **agrupados por tipo**
- O detalhe de um serviço: o que há a mostrar (domínio, utilizador,
  servidor, valores, datas, estado, disco, banda, IP)

**A app**
- Um endpoint novo: `GET /api/v1/client/services`
- Um ecrã novo na app: **Serviços**, com o tipo de cada um
- A entrada no menu (e no painel do cliente)

**Os dados de teste**
- A conta de teste passa a ter um serviço de **cada** família, para que
  a diferença seja visível e testável

### Out of scope

- Criar, alterar ou cancelar serviços
- As páginas de configuração de produtos
- A facturação dos serviços

## Acceptance Criteria

- [ ] AC1 — O detalhe do cliente mostra os **tipos** dos serviços, e
      não uma etiqueta única
- [ ] AC2 — Os serviços de Backup aparecem como Backup
- [ ] AC3 — O detalhe de um serviço mostra os seus campos
- [ ] AC4 — A app tem um ecrã de **Serviços**
- [ ] AC5 — A API devolve o tipo de cada serviço
- [ ] AC6 — O tipo vem do **produto** (a fonte da verdade), e não de
      uma lista escrita à mão
- [ ] AC7 — Todos os portões verdes
