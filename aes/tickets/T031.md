# T031 — Sistema de Recuperação de Credenciais

## Contexto

O login falhava e a única via era um `UPDATE` manual na base de dados. Isso
não é recuperação de credenciais — é acesso directo à base. O operador
pediu um sistema.

ARestrictions estruturais:

- **O esquema de produção não pode mudar.** A base é o WHMCS de produção.
- **Não há SMTP configurado.** A entrega do token tem de funcionar sem
  servidor de correio, ou degradar honestamente.
- **Não se pode revelar se uma conta existe.** A resposta tem de ser
  igual em qualquer caso.

## Scope

### In scope

**Recuperação de cliente**
- `POST /api/v1/auth/forgot-password` {email} — resposta **idêntica**
  exista ou não a conta
- Gera um token, grava-o em `tblclients.pwresetkey` + `tblclients.pwresetexpiry`
  (as colunas que o WHMCS 5.3.9 já tem — **zero alteração de esquema**)
- `POST /api/v1/auth/reset-password` {token, password} — valida o token e a
  expiração, grava bcrypt, limpa o token
- Entrega do token: SMTP quando configurado; caso contrário, o token é
  escrito num ficheiro local que o administrador lê e entrega

**Recuperação de administrador**
- `tbladmins` **não tem** colunas de reset, e não se pode adicionar
  colunas à base de produção
- O token vive num **ficheiro** no contentor (`storage/reset-tokens/`), com
  expiração — zero alteração de esquema
- `POST /api/v1/admin/auth/forgot-password` e `.../reset-password`
- A página de login do admin passa a ter o link

**Interface**
- Flutter: ecrã "Recuperar senha" (pedido) e "Definir nova senha" (token)
- O link "Esqueci a senha?" da app passa a abrir o ecrã real

**Ferramentas**
- `make db-reset-tokens` — lista os tokens pendentes
- `make db-reset-client EMAIL=...` — repõe a senha de um cliente

### Out of scope

- Alterar o esquema de produção
- Configurar SMTP (não há credenciais)
- Autenticação de dois factores
- Notificações push

## Acceptance Criteria

- [ ] AC1 — Pedir a recuperação nunca revela se a conta existe
- [ ] AC2 — O token do cliente vive nas colunas `pwresetkey`/`pwresetexpiry`
      reais (sem alteração de esquema)
- [ ] AC3 — O token expira
- [ ] AC4 — O token só pode ser usado uma vez
- [ ] AC5 — A nova senha é gravada em bcrypt
- [ ] AC6 — Sem SMTP, o token é entregue de forma utilizável e o operador
      sabe onde o encontrar
- [ ] AC7 — O admin tem o mesmo fluxo, sem alterar o esquema
- [ ] AC8 — A app Flutter tem os ecrãs do fluxo
- [ ] AC9 — `make db-reset-tokens` e `make db-reset-client` funcionam
- [ ] AC10 — Todos os portões verdes
