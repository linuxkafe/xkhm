# T021 — Playwright E2E Test Harness (PHP backend)

## Context

The operator requires that **every** change be validated with Playwright, not just unit
tests. Today the repository has `tests/E2E` (empty) and `tests/Playwright` (empty). This
ticket establishes a runnable, repeatable Playwright harness against the Docker-deployed
PHP backend at `http://localhost:8083`.

## Scope

### In scope
- Python Playwright package (already installed: `playwright 1.63.0`) with a
  `pytest`-compatible suite under `tests/Playwright/`
- `conftest.py` with base URL fixture, container readiness gate, and per-test
  browser context isolation
- Coverage of: public pages, admin login/logout, client login, protected-route
  redirect behaviour, knowledgebase, announcements, domain checker, server status,
  API endpoint
- A `make e2e` target and a documented one-liner to run against the Docker stack
- Screenshot + trace capture on failure (Playwright built-ins)

### Out of scope
- Load/perf testing (T020 in kanban is separate)
- CI wiring (no CI provider configured in this repo)

## Acceptance Criteria

- [ ] AC1 — `make e2e` runs the suite against `http://localhost:8083`
- [ ] AC2 — Suite skips (not fails) when the Docker stack is down, with a clear message
- [ ] AC3 — Admin login → `/admin` returns 200; logout → 302 to login page
- [ ] AC4 — Unauthenticated `/admin` returns 302 to `/admin/login.php`
- [ ] AC5 — Client login with a `linuxkonect` client → `/clientarea.php` returns 200
- [ ] AC6 — Every public page renders without console errors and without 404 assets
- [ ] AC7 — Traces/screenshots archived under `tests/Playwright/artifacts/` on failure
