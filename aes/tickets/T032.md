# T032 — Rodar a senha do MySQL + entrega de correio pelo Postfix local

## Contexto

Duas decisões do operador:

1. **«Podes rodar a senha do mysql»** — a senha de produção está comprometida
   (T027): foi publicada em `0.0.0.0:3306`, vive em `configuration.php` e
   em 10+ commits do git.
2. **«Podes usar o localhost 25 sem autenticação para o mail»** — há um
   Postfix no host, na porta 25, sem autenticação para o loopback. A
   recuperação de credenciais pode entregar o token **por correio**.

O T031 deixou o token num ficheiro porque não havia SMTP. Agora há.

## O que a reconhecimento encontrou

| Facto | Evidência |
|-------|-----------|
| A base de **produção** (`10.0.3.1:3306`) **não é alcançável** | `ip route get` devolve a rota, mas a porta dá timeout; o ping também não responde |
| A senha de produção está em **10 ficheiros versionados** | `.env.production`, `configuration.php`, `docker-compose.yml`, `CLAUDE.md`, `docs/ROADMAP.md`, `aes/shadow/SD-OPS-001.md`, `aes/tickets/T002-plan.md`, `aes/tickets/T027.md` |
| E em **10+ commits** | `git log -S` |
| O `healthcheck` do compose usa a senha de **produção** contra a base **local** | `docker-compose.yml:69` — e passa porque o `mysqladmin ping` não verifica a autenticação |
| O MySQL **local** tem credenciais próprias | `linuxkonect`/`xkhm-local-only`, publicado só em `127.0.0.1:13306` |
| O Postfix escuta em `0.0.0.0:25`, sem autenticação para o loopback | `mynetworks = 127.0.0.0/8`; `smtpd_relay_restrictions = permit_mynetworks` |
| O contentor **não tem** caminho para o host | portas 25, 53 e 8083 dão timeout a partir do contentor; o firewall do host bloqueia, e não há sudo |
| O **remetente** autorizado pelo relay é `safedata@linuxkafe.com` | o relay é a Brevo; com outro `From` devolve `451 4.0.0 Invalid from` |
| O correio **sai** com esse remetente | `/var/mail/root` foi actualizado; a fila do Postfix não cresceu |
| O `crontab` do utilizador **corre** | sonda verificada; o `cron` do sistema está a correr |
| A porta 80 do host está ocupada | `network_mode: host` não é opção |
| `tbladmins` **tem** `email` | `linuxkafe` → `mail@linuxkafe.com` |

## Scope

### In scope

**Rotação do MySQL**
- Rodar a senha do MySQL **local** (o único ao alcance) — utilizador da
  aplicação e `root`
- Tirar a senha de produção de **todos** os ficheiros versionados
- Corrigir o `healthcheck` do compose (usa a senha errada)
- Tirar os *defaults* inseguros do compose e do `Makefile`; as
  credenciais passam a viver num `.env` **não versionado**, com modo 0600
- Uma ferramenta de rotação para a base de **produção**, que verifica o
  resultado (a senha antiga falha, a nova funciona)
- Documentar o que **não** foi possível daqui e o comando exacto para
  o operador

**Entrega de correio**
- `SmtpTokenDelivery` passa a suportar SMTP **sem autenticação** (porta 25)
- A promessa do T031 passa a ser cumprida: o ficheiro é **sempre**
  escrito, mesmo quando há SMTP
- Um **correio do host** (`tools/mail_pending_tokens.py`) entrega os tokens
  pendentes por `127.0.0.1:25`, com o `From` autorizado, e apaga o
  ficheiro depois de entregar
- O token do administrador é entregue ao **email** do administrador
  (`tbladmins.email`), não ao nome de utilizador

### Out of scope

- Reescrever o histórico do git (destrutivo, e a rotação já torna a
  senha velha inútil)
- Configurar SMTP autenticado
- Ligar a Brevo / mexer na configuração do Postfix
- Tocar no servidor de produção (inalcançável)
