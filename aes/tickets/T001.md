# T001 — REA Analysis of Live WHMCS Service + Project Scaffold

## Context

This is the first ticket for the xkhm project. The goal is to:
1. Establish the AES project structure (done in Phase 0)
2. Use REA to analyze the live WHMCS service at `xk.linuxkafe.com`
3. Document all observable features, endpoints, and behaviors
4. Produce a comprehensive feature inventory that will drive the reimplementation

## Acceptance Criteria

- [ ] AC1 — All public-facing pages enumerated with their HTTP status codes
- [ ] AC2 — All API endpoints identified and documented
- [ ] AC3 — Database schema surveyed (tables, columns, relationships)
- [ ] AC4 — Module inventory (gateways, servers, addons, fraud, antispam) mapped to live features
- [ ] AC5 — Language/locale confirmed (pt_BR)
- [ ] AC6 — Configuration values extracted from live container
- [ ] AC7 — Feature parity baseline established (what exists on live vs what's missing)
- [ ] AC8 — Plan document written with architecture decision record

## Scope

**In scope:**
- REA analysis of the live service (https://xk.linuxkafe.com/)
- Database schema survey via the live connection
- Module and feature inventory
- Configuration extraction
- Architecture decision record

**Out of scope:**
- Any code implementation
- Modifying the live service
- Continuing ionCube stripping work (that's in `/home/seyon/dev/whmcs/`)

## Dependencies

- `/home/seyon/dev/whmcs-original/` — read-only WHMCS source
- `/home/seyon/dev/whmcs/` — reconstruction artifacts
- Live service at `xk.linuxkafe.com`
- Docker containers: `whmcs-app`, `whmcs-mysql`

## Known Risks

- The live DB (`linuxkonect`) may not be accessible from this machine directly — may need to query via the whmcs-app container
- Some features may be behind admin authentication and require credentials
- The ionCube Loader prevents static analysis of encrypted files
