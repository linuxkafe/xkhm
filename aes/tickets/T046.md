# T046 — O cron — e os avisos que não saem para os clientes

## Contexto

O operador: «o cron que disparava avisos de pagamento já está
implementado? nesta fase não convém disparar para clientes até
validação, apenas deve ser disparado para `mail@linuxkafe.com` se
necessário».

**A resposta à primeira pergunta é não.** O `cron.php` do WHMCS não
existe no xkhm. O que existe é:

- a **geração** do aviso de pagamento (T038) — a fila e o PDF;
- o **correio do host** (`tools/mail_pending_tokens.py`), que entrega
  a fila de minuto a minuto;
- mas **nada que gere as faturas** de renovação, aplique a multa
  por atraso, suspenda os serviços em atraso, ou **dispare** os
  avisos.

O único `crontab` do projecto é o do correio:

```
* * * * * /usr/bin/python3 .../tools/mail_pending_tokens.py >> .../storage/mailer.log 2>&1
```

## A restrição do operador

> «nesta fase não convém disparar para clientes até validação, apenas
> deve ser disparado para `mail@linuxkafe.com` se necessário»

Esta restrição é o **requisito mais importante** do ticket, e tem de
ser imposta **no código**, e não por convenção. Um cliente real não
pode receber um aviso de pagamento de um sistema que ainda não está
validado — e o pior modo de falhar é o silencioso: o aviso sai, e
ninguém sabe.

## O que se propõe

1. **O ciclo** (`/api/v1/cron` ou um comando), que faz o que o
   `cron.php` do WHMCS faz:
   - as faturas de **renovação** dos serviços cujo `nextinvoicedate`
     chegou;
   - a **multa por atraso** das faturas vencidas;
   - a **suspensão** dos serviços em atraso (configurável);
   - os **avisos de pagamento** das faturas por vencer e das
     vencidas.
2. **A restrição**, imposta em **dois** portões:
   - a aplicação **não enfileira** o aviso para o cliente — enfileira
     para o endereço do operador;
   - o **correio do host** recusa qualquer destinatário que não
     esteja na lista permitida, e manda a mensagem para `failed/`
     com o motivo.
3. O **registo** do que o ciclo fez (`tblactivitylog`, que o WHMCS
   também usa).

## Acceptance criteria

- [ ] AC1 — O ciclo gera a fatura de **renovação** do serviço que
      chegou à data
- [ ] AC2 — O ciclo aplica a **multa por atraso** à fatura vencida
- [ ] AC3 — O ciclo **não** envia nada para os clientes: o aviso vai
      para `mail@linuxkafe.com`
- [ ] AC4 — O **correio** recusa um destinatário fora da lista, e
      diz porquê
- [ ] AC5 — O ciclo é **idempotente**: correr duas vezes não gera
      duas faturas
- [ ] AC6 — O que o ciclo fez fica registado
- [ ] AC7 — Todos os portões verdes
