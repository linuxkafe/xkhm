# T023 — Dark Mode Automático + Compatibilidade Mobile

## Context

O operador exige duas coisas que o sistema actual não tem:

1. **Dark mode automático** — a aplicação deve seguir a preferência do
   sistema (`prefers-color-scheme` no CSS, `ThemeMode.system` no Flutter),
   sem interruptor manual.
2. **Máxima compatibilidade mobile** — tanto no site PHP/CSS como na
   aplicação Flutter, incluindo telemóveis reais (safe areas, notch, alvo de
   toque, teclado virtual).

O requisito de dark mode é襟难点 na arquitectura actual: a paleta vive num
ficheiro de tokens único gerado para CSS e Dart. Suportar dois modos exige
uma paleta por modo, e a *forma* dessa paleta tem de ser decideda antes de
qualquer linha de código — caso contrário os dois clientes divergem.

## Scope

### In scope

**Dark mode**
- Tokens escuros em `assets/design_tokens.json` (secção nova `dark`)
- `tools/sync_tokens.py` gera o bloco `@media (prefers-color-scheme: dark)`
  em `tokens.css` e as constantes `LkColors.dark*` em `tokens.dart`
- Flutter: `ThemeMode.system` + `LkTheme.dark()` derivado dos tokens escuros
- CSS: `color-scheme: light dark` + bloco de media query
- Persistência da preferência: o sistema é a fonte da verdade; o override
  manual fica **fora** do âmbito (ver T024)

**Mobile**
- CSS: alvos de toque ≥ 44px, `viewport-fit=cover`, `env(safe-area-inset-*)`,
  tabelas que não rebentam em ecrãs estreitos, navegação que colapsa
- Flutter: `SafeArea`, `MediaQuery` para larguras, alvos de toque, teclado
  virtual (`viewInsets`), `NavigationBar` em vez de `NavigationRail` no
  estreito (já existe), drawer para navegação completa no mobile
- Flutter: `android:windowSoftInputMode=adjustResize`, permissões iOS

**Testes**
- Playwright: `prefers-color-scheme` (dark) em ambos os clientes
- Playwright: viewports mobile (360×640, 390×844) em ambos os clientes
- Flutter: widget tests para os dois temas

### Out of scope

- Interruptor manual de tema (I/O na app) → **T024**
- Tradução para outros idiomas
- PWA / service worker offline
- Notificações push
- Tabelas do WHMCS ou alterações ao esquema

## Acceptance Criteria

- [ ] AC1 — O site PHP segue `prefers-color-scheme`: em dark, o fundo é
      escuro e o texto é claro, **sem** JavaScript
- [ ] AC2 — A aplicação Flutter segue o tema do sistema
      (`ThemeMode.system`), alternando sem reiniciar
- [ ] AC3 — A paleta escura é gerada do **mesmo** ficheiro de tokens
      (`assets/design_tokens.json`); não existe literal de cor escrito à mão
- [ ] AC4 — Nenhum literal hexadecimal nos fontes Dart
      (`make tokens-check` passa)
- [ ] AC5 — Em 360 px de largura nenhuma página do PHP tem scroll horizontal
- [ ] AC6 — Todos os alvos interactivos têm ≥ 44×44 px
- [ ] AC7 — A aplicação Flutter não é interrompida pelas safe areas
      (notch, barra de gestos) nem pelo teclado virtual
- [ ] AC8 — A navegação no Flutter em ecrãs estreitos mostra **todas** as
      secções (hoje a barra inferior mostra apenas 4 de 7)
- [ ] AC9 — Playwright passa com `prefers-color-scheme: dark` e com
      viewports mobile, para o PHP e para o Flutter
- [ ] AC10 — `make test`, `make lint`, `make e2e`, `make flutter-test`,
      `make tokens-check` todos verdes
