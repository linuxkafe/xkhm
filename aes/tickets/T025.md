# T025 — Migração Completa para Flutter (retirar o front-end PHP)

## Context

O operador决定 migrar completamente para Flutter: as páginas PHP deixam de ser
o cliente e passam a ser apenas a API.

Hoje o PHP serve **duas** coisas: a API `/api/v1` (que o Flutter consome) e as
páginas HTML (que o Flutter não usa). Migrar completamente significa que o
HTML sai do caminho de produção — mas **a API e a base de dados ficam**, porque
a base de dados é o WHMCS de produção e não se replica no cliente.

O risco principal é exacto: se as páginas PHP saírem e o Flutter não cobrir
alguma funcionalidade, o cliente fica sem porta de entrada. Por isso a
retirada tem de ser **coberta por testes**, não por confiança.

## Scope

### In scope

- **Cobertura funcional**: inventário de cada rota PHP e do que a app Flutter
  faz em vez dela. Tudo o que a app não cobre fica na API (para integrações) mas
  sai do *front-end*.
- **Rotas**: as páginas HTML deixam de ser registadas. `/` passa a ser a app
  Flutter (redireccionamento ou servida directamente).
- **Flutter**: passa a servir a totalidade do fluxo de cliente — login, painel,
  faturas (+ detalhe), domínios, tickets (+ detalhe + criar), base de
  conhecimento, anúncios, verificador de domínios, estado do servidor, perfil.
- **Erros e 404** em Flutter, não em HTML.
- **Testes**: a suíte E2E passa a apontar para a app; o PHP só é testado como API.
- **Documentação**: `docs/FLUTTER.md` reflecte a nova topologia.

### Out of scope

- O *admin panel* em Flutter (ticket separado — a API de admin não existe ainda).
- Migrar o backend para outra linguagem. O PHP/Slim **fica**.
- Mover a base de dados. A base de dados de produção fica onde está.

## Acceptance Criteria

- [ ] AC1 — Inventário rota a rota: cada página PHP tem uma contrapartida na
      app Flutter, ou uma decisão explícita de "API only"
- [ ] AC2 — Nenhuma rota HTML em produção; `/` entrega a app Flutter
- [ ] AC3 — A app Flutter cobre todos os fluxos de cliente que as páginas
      faziam (ver AC1)
- [ ] AC4 — A suíte E2E passa contra a app Flutter; o PHP é testado como API
- [ ] AC5 — Erros 404/500 são apresentados pela app, em pt-BR
- [ ] AC6 — `make test`, `make lint`, `make e2e`, `make flutter-test`,
      `make tokens-check` verdes
- [ ] AC7 — Documentação actualizada
