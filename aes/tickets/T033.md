# T033 — O e-mail da recuperação leva um link, e o link leva ao formulário

## Contexto

O operador recebeu o e-mail da recuperação e a resposta foi: «isto não
são bem instruções». O e-mail dizia:

```
Codigo: 6c8ea5a08c2e7c638e0994845466b6ea8a15a67684a9b2c70d4eb71c262407fe
```

O utilizador tem de copiar o código, abrir a aplicação, e colá-lo num
campo. Isso é um e-mail de 1998: o correio transporta **links**, não
instruções para copiares coisas.

E ao olhar para o fluxo do **administrador**, há um problema mais
grave: **não existe página onde introduzir o código**. O token chega,
e não há onde o meter. O fluxo do admin está **incompleto**.

## Reconhecimento

| Facto | Evidência |
|-------|-----------|
| O e-mail leva um código, não um link | `tools/mail_pending_tokens.py` — `build_message()` |
| O fluxo do admin **não tem** onde introduzir o token | `AdminAuthController` tem `showLogin`/`login`/`logout` e o formulário de *pedido*; não há formulário de *definição* |
| O cliente tem onde introduzir o código | `password_reset_screen.dart` — campo `reset-token` |
| A app web não tem rotas nomeadas | `main.dart` — `home: const _Root()`, comutado pelo estado da sessão |
| A app web é **tudo do mesmo origin** | CanvasKit local, fontes empacotadas — nada de terceiros |
| O token num **URL** pode vazar para o log do servidor | o `Access Log` do Apache regista a *query string* |
| O **fragmento** (`#…`) nunca é enviado ao servidor | por desenho do HTTP |

## Scope

### In scope

**O e-mail**
- Leva um **link** como acção principal, e o código como alternativa
  (quem lê o correio noutro dispositivo não tem o link à mão)
- Formato `multipart/alternative`: texto simples e HTML
- O link aponta para o sítio público, que vem da configuração

**O cliente (Flutter)**
- A app lê o token do **fragmento** (`#reset=…`) — que o navegador
  **nunca envia ao servidor**, logo não vai parar ao log de acessos
- Pré-preenche o campo e **limpa o URL**, para o token não ficar no
  histórico
- Aceita também `?reset=…` (fallback)
- O link abre o ecrã de recuperação mesmo com a sessão iniciada

**O administrador (PHP)**
- Uma página **«definir a nova senha»**, que hoje não existe
- O link traz o token; a página **redireciona** logo de seguida, para
  o token sair do campo de endereço
- O formulário tem o token num campo escondido e faz `POST`

**A configuração**
- `XKHM_PUBLIC_URL` — o endereço público, de onde se constroem os links

### Out of scope

- SMTP autenticado
- Um servidor de links com expiração própria
- Redesenhar o e-mail com imagens e logótipos
- Mover o painel de administração para o Flutter

## Acceptance Criteria

- [ ] AC1 — O e-mail contém um **link** clicável para definir a senha
- [ ] AC2 — O link leva o utilizador ao formulário, com o token
      preenchido
- [ ] AC3 — O link do cliente **não** passa pelo servidor (fragmento),
      logo não fica no log de acessos
- [ ] AC4 — O token é **removido do URL** depois de lido
- [ ] AC5 — O administrador tem uma página para definir a nova senha
- [ ] AC6 — O token do administrador sai do campo de endereço
- [ ] AC7 — O código continua disponível como alternativa (copiar/colar)
- [ ] AC8 — O e-mail tem uma versão de texto simples e uma de HTML
- [ ] AC9 — O link aponta para o endereço público configurado
- [ ] AC10 — Todos os portões verdes
