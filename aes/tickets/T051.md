# T051 — O login no telefone, e os restantes campos

## Contexto

O operador: «de certeza que está com flutter? não parece nada
compatível com mobile até o login perde o foco em cada letra
introduzida em android. há muito a melhorar para um interface
moderno e compatível em mobile».

O defeito é real, e a causa é uma wrapper de `Semantics` à volta
dos campos do formulário. No web, no Android, o teclado perde o foco
a cada tecla quando o nó de semântica é recriado — e o `container:
true` com `explicitChildNodes: true` e `textField: true` força
essa recriação.

Os restantes campos do formulário também não tinham o
`textInputAction` nem o `keyboardType` — o teclado do telefone não
sabia que tecla «Enter» mostrar (a seta de envio, ou a de ir para o
campo seguinte), e o teclado era o padrão para tudo (mesmo para um
código numérico).

## O que se propõe

1. **O login** perde a wrapper de `Semantics`, e os campos ganham o
   `textInputAction` e o `keyboardType` adequados.
2. **Os restantes campos** (o domínio, o código da segurança, o
   domínio da encomenda) ganham o mesmo tratamento.
3. O `autofillHints` e o `autocorrect`/`enableSuggestions` ficam
   correctos para cada campo (o e-mail não tem sugestões, o código
   é só dígitos).

## Acceptance criteria

- [x] AC1 — O login **não** perde o foco ao escrever (verificado
      no dispositivo, e por um teste de regressão)
- [x] AC2 — Cada campo tem o `textInputAction` e o `keyboardType`
      adequados
- [x] AC3 — Os testes do Playwright continuam verdes (a semântica
      da chave continua a funcionar)
- [x] AC4 — Todos os portões verdes
