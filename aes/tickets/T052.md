# T052 — O motor de renderização HTML (mobile first)

## Contexto

O operador: «de certeza que está com flutter? não parece nada
compatível com mobile até o login perde o foco em cada letra
introduzida em android. há muito a melhorar para um interface
moderno e compatível em mobile».

A aplicação é Flutter, mas a renderização por omissão é a
**CanvasKit** (ou a **skwasm**, no Flutter 3.47). Ambas desenham o
interface num `<canvas>`, e o texto é desenhado pelo motor de
renderização, não pelo navegador.

No Android web, isso significa: o teclado suave do navegador não
sabe que existe um campo de texto, e a composição IME passa por
um elemento `<input>` escondido. Quando o motor repinta (o que
acontece a cada keystroke, porque o `setState` dispara), o foco
perde-se.

O motor **HTML** usa os elementos nativos do navegador (`<input>`,
`<select>`, …). O teclado suave trata-os como campos nativos: o
foco mantém-se, a composição IME funciona, e a acessibilidade é
a do navegador.

## O que se propõe

1. A build passa a usar `--web-renderer=html` (mobile first).
2. A build é testada com o Playwright, e o teste do login ganha um
   teste de regressão para o foco (o que só se verifica no
   dispositivo, mas a build tem de ser a certa).
3. A documentação diz que o motor é o HTML, e porquê.

## Acceptance criteria

- [ ] AC1 — A build usa o motor HTML
- [ ] AC2 — Os testes do Playwright continuam verdes
- [ ] AC3 — A aplicação carrega e renderiza no Chrome
- [ ] AC4 — Todos os portões verdes
